# Multi-Modal Edge Artificial Intelligence System for Oil Pipeline Integrity Monitoring

Simulation and monitoring dashboard for the project *Design and Implementation of a Multi-Modal Edge
Artificial Intelligence System for Oil Pipeline Integrity Monitoring* (Ogechukwu Marycynthia Nwankwo).

> **Simulation mode.** All sensor data in this repository are generated by `simulator.py`.
> Staging real attacks on live pipelines is unsafe and illegal, so the classifier and the dashboard
> are evaluated on simulated vibration, acoustic and light signals.

## What the system does

1. **Simulates** the three sensor channels of a field node (vibration and acoustic at 12.8 kHz, four
   photodiodes) for five event classes: environmental noise, illegal hot-tapping, artisanal refining,
   sabotage (torch-cutting) and vehicle/boat activity. Distance, background noise, day/night and
   overlapping rain, thunder, wind and engines are randomised.
2. **Extracts 128 features** per 0.5 s window: 32 vibration band energies, 40 acoustic MFCCs,
   16 light statistics and 40 vibration–acoustic cross-correlation lags.
3. **Trains** the proposed Temporal Convolutional Network (TCN) and the baselines (threshold rule,
   SVM, Random Forest, LSTM, GRU), runs an ablation study over the sensor combinations, and quantizes
   the TCN to 8-bit TensorFlow Lite for the ESP32 (`models/model_data.h`).
4. **Runs a live dashboard** in which 15 simulated nodes in five clusters in Rivers State generate
   events, classify them on the node, and send alerts (LoRaWAN, or satellite backup) to the monitoring
   centre.

## Run it in GitHub Codespaces (no installation)

1. On this repository page click **Code → Codespaces → Create codespace on main**.
2. Wait for the set-up to finish. The first time, it installs the packages and runs `python train.py`
   (about 10–15 minutes on the free 2-core machine).
3. The dashboard starts automatically. If it does not open by itself, open the **Ports** tab and click
   the globe icon next to port **8501**. To start it manually: `streamlit run app.py`.
4. Sign in with one of the demo accounts:

| User | Role | Password |
|---|---|---|
| Duty Officer | Security Personnel | `security123` |
| Field Technician | Field Technician | `tech123` |

Free GitHub accounts include 120 core hours of Codespaces per month (60 hours on a 2-core machine).
Stop the codespace when you are not using it.

## Run it on your own computer

```bash
pip install -r requirements.txt
python train.py          # full run; use --quick for a 1-minute check
streamlit run app.py
```

## Dashboard pages

| Page | What it shows |
|---|---|
| Live monitoring | Simulated clock, key figures, node map (red = alert in the last hour), latest alerts |
| Alert management | Pending alerts with GPS position; security personnel confirm or reject them (stored in the RESPONSE table) |
| Device health | Battery, temperature and humidity for each node; battery history; maintenance (technician) |
| Signal viewer | Vibration and acoustic waveforms, vibration spectrum, light sensors and classifier probabilities of the latest event |
| Model performance | Accuracy, macro F1, inference time and size of every model; confusion matrices; ablation study; live session statistics |

Use **Trigger a test event** in the sidebar to send a chosen event (for example hot-tapping) to a chosen node.

## Repository structure

```
app.py            Streamlit dashboard
engine.py         simulation engine (clock, power model, events, alerts)
simulator.py      synthetic vibration, acoustic and light signals
features.py       128-element feature extraction
train.py          dataset generation, training, evaluation, TFLite export
database.py       SQLite database (Section 3.5 design)
firmware/         ESP32 field-node firmware (reference design)
models/           trained models (created by train.py)
results/          metrics.json and figures for Chapter Four (created by train.py)
.devcontainer/    Codespaces configuration
```

## Notes for the report

* `results/metrics.json`, `results/confusion_*.png` and `results/ablation.png` contain the figures to
  report in Section 4.7. They change if the simulation or the random seed changes.
* Inference times in the dashboard are measured on the computer running it. The latency of the int8 TCN
  on the ESP32 must be measured on the board.
* Field-deployment results are not produced by this repository.
